Atualizando o estado com base no estado anterior.
Suponha que o agevalor seja 42. Este manipulador é chamado setAge(age + 1)três vezes:

function handleClick() {
  setAge(age + 1); // setAge(42 + 1)
  setAge(age + 1); // setAge(42 + 1)
  setAge(age + 1); // setAge(42 + 1)
}
No entanto, após um clique, ageserá apenas 43em vez de 45! Isso ocorre porque chamar a setfunção não atualiza a agevariável de estado no código já em execução. Portanto, cada setAge(age + 1)chamada se torna setAge(43).

Para resolver esse problema, você pode passar uma função de atualização em setAgevez do próximo estado:

function handleClick() {
  setAge(a => a + 1); // setAge(42 => 43)
  setAge(a => a + 1); // setAge(43 => 44)
  setAge(a => a + 1); // setAge(44 => 45)
}
Aqui a => a + 1está sua função de atualização. Ela recebe o estado pendente e calcula o próximo estado a partir dele.

O React coloca suas funções de atualização em uma fila. Então, durante a próxima renderização, ele as chamará na mesma ordem:

a => a + 1receberá 42como estado pendente e retornará 43como o próximo estado.
a => a + 1receberá 43como estado pendente e retornará 44como o próximo estado.
a => a + 1receberá 44como estado pendente e retornará 45como o próximo estado.
Não há outras atualizações na fila, então o React armazenará 45o estado atual ao final.

Por convenção, é comum nomear o argumento de estado pendente com a primeira letra do nome da variável de estado, como `pending` apara `pending` age. No entanto, você também pode chamá-lo de `pending` prevAgeou algo que considere mais claro.

O React pode chamar seus atualizadores duas vezes durante o desenvolvimento para verificar se eles são puros.

Armazenar informações de renderizações anteriores
Normalmente, você atualizará o estado nos manipuladores de eventos. No entanto, em casos raros, você pode querer ajustar o estado em resposta à renderização — por exemplo, você pode querer alterar uma variável de estado quando uma propriedade for alterada.

Na maioria dos casos, você não precisa disso:

Se o valor que você precisa puder ser calculado inteiramente a partir das props atuais ou de outro estado, remova esse estado redundante por completo. Se você estiver preocupado com a necessidade de recálculos frequentes, o useMemoHook pode ajudar.
Se você deseja redefinir o estado de toda a árvore de componentes, passe um valor diferente keypara o seu componente.
Se possível, atualize todo o estado relevante nos manipuladores de eventos.
Na rara hipótese de nenhuma dessas situações se aplicar, existe um padrão que você pode usar para atualizar o estado com base nos valores que já foram renderizados, chamando uma setfunção enquanto seu componente está sendo renderizado.

Aqui está um exemplo. Este CountLabelcomponente exibe a countpropriedade que lhe foi passada:

export default function CountLabel({ count }) {
  return <h1>{count}</h1>
}
Suponha que você queira mostrar se o contador aumentou ou diminuiu desde a última alteração. A countpropriedade não informa isso — você precisa manter o controle do seu valor anterior. Adicione uma prevCountvariável de estado para rastreá-lo. Adicione outra variável de estado chamada ` trendcount` para armazenar se a contagem aumentou ou diminuiu. Compare `count` prevCountcom count`count` e, se forem diferentes, atualize `count` prevCounte `count` trend. Agora você pode mostrar tanto a contagem atual quanto a variação desde a última renderização .




import { useState } from 'react';

export default function CountLabel({ count }) {
  const [prevCount, setPrevCount] = useState(count);
  const [trend, setTrend] = useState(null);
  if (prevCount !== count) {
    setPrevCount(count);
    setTrend(count > prevCount ? 'increasing' : 'decreasing');
  }
  return (
    <>
      <h1>{count}</h1>
      {trend && <p>The count is {trend}</p>}
    </>
  );
}

Esse padrão pode ser difícil de entender e geralmente é melhor evitá-lo. No entanto, é melhor do que atualizar o estado em um efeito. Quando você chama a setfunção durante a renderização, o React renderizará novamente esse componente imediatamente após o seu componente sair com uma returninstrução e antes de renderizar os filhos. Dessa forma, os filhos não precisam ser renderizados duas vezes. O restante da função do seu componente ainda será executado (e o resultado será descartado). Se a sua condição estiver abaixo de todas as chamadas de Hook, você pode adicionar um `setTimeout` antecipado return;para reiniciar a renderização mais cedo.

Solução de problemas
Atualizei o estado, mas o registro de logs continua mostrando o valor antigo.
Chamar a setfunção não altera o estado do código em execução :

function handleClick() {
  console.log(count);  // 0

  setCount(count + 1); // Request a re-render with 1
  console.log(count);  // Still 0!

  setTimeout(() => {
    console.log(count); // Also 0!
  }, 5000);

Isso ocorre porque os estados se comportam como um instantâneo. Atualizar o estado solicita outra renderização com o novo valor do estado, mas não afeta a countvariável JavaScript no seu manipulador de eventos já em execução.

Se precisar usar o próximo estado, você pode salvá-lo em uma variável antes de passá-lo para a setfunção:

Atualizei o estado, mas a tela não atualiza.
O React ignorará sua atualização se o próximo estado for igual ao estado anterior, conforme determinado por uma Object.iscomparação. Isso geralmente acontece quando você altera um objeto ou um array diretamente no estado.

obj.x = 10;  // 🚩 Wrong: mutating existing object
setObj(obj); // 🚩 Doesn't do anything
Você modificou um objobjeto existente e o passou de volta para setObjo React, então a atualização foi ignorada. Para corrigir isso, você precisa garantir que sempre substitua objetos e arrays no estado em vez de modificá -los .

// ✅ Correct: creating a new object
setObj({
  ...obj,
  x: 10
});
Estou recebendo o erro: “Muitas renderizações repetidas”
Você pode receber um erro que diz: Too many re-renders. React limits the number of renders to prevent an infinite loop.Normalmente, isso significa que você está definindo o estado incondicionalmente durante a renderização , fazendo com que seu componente entre em um loop: renderizar, definir o estado (o que causa uma nova renderização), renderizar, definir o estado (o que causa uma nova renderização) e assim por diante. Muitas vezes, isso é causado por um erro na especificação de um manipulador de eventos.

// 🚩 Wrong: calls the handler during render
return <button onClick={handleClick()}>Click me</button>

// ✅ Correct: passes down the event handler
return <button onClick={handleClick}>Click me</button>

// ✅ Correct: passes down an inline function
return <button onClick={(e) => handleClick(e)}>Click me</button>
Se não conseguir encontrar a causa desse erro, clique na seta ao lado do erro no console e examine a pilha de chamadas JavaScript para encontrar a setchamada de função específica responsável pelo erro.

Minha função de inicialização ou atualização é executada duas vezes.
No modo estrito , o React chamará algumas de suas funções duas vezes em vez de uma:

function TodoList() {
  // This component function will run twice for every render.

  const [todos, setTodos] = useState(() => {
    // This initializer function will run twice during initialization.
    return createTodos();
  });

  function handleClick() {
    setTodos(prevTodos => {
      // This updater function will run twice for every click.
      return [...prevTodos, createTodo()];
    });
  }
  // ...
Isso é esperado e não deve quebrar seu código.

Esse comportamento , exclusivo para desenvolvimento, ajuda a manter os componentes puros. O React usa o resultado de uma das chamadas e ignora o resultado da outra. Contanto que seu componente, inicializador e funções de atualização sejam puros, isso não deve afetar sua lógica. No entanto, se eles forem acidentalmente impuros, isso ajuda a identificar os erros.

Por exemplo, esta função de atualização impura modifica um array no estado:

setTodos(prevTodos => {
  // 🚩 Mistake: mutating state
  prevTodos.push(createTodo());
});
Como o React chama sua função de atualização duas vezes, você verá que o item da lista de tarefas foi adicionado duas vezes, o que indica que há um erro. Neste exemplo, você pode corrigir o erro substituindo o array em vez de modificá-lo :

setTodos(prevTodos => {
  // ✅ Correct: replacing with new state
  return [...prevTodos, createTodo()];
});
Agora que essa função de atualização é pura, chamá-la uma vez a mais não altera o comportamento. É por isso que o React chamá-la duas vezes ajuda a encontrar erros. Apenas as funções de componente, inicializador e atualização precisam ser puras. Os manipuladores de eventos não precisam ser puros, portanto o React nunca os chamará duas vezes.

Leia o artigo "Como manter os componentes puros" para saber mais.

Estou tentando atribuir um estado a uma função, mas ela está sendo chamada em vez disso.
